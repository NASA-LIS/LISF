# NLDAS-3 Retrospective Surface Meteorology Generation

## Overview

This directory contains the LIS configuration file, supporting tables, and a Fortran merge utility used to generate hourly 1-km MERRA-2-based retrospective meteorological forcing fields for the NASA North American Land Data Assimilation System Phase 3 (NLDAS-3). These hourly outputs are intermediate products that are subsequently merged into one daily NetCDF file per day, with all 24 hourly timesteps preserved.

The resulting daily merged files provide the surface meteorology inputs used by the downstream retrospective merge workflow, while the hourly `LWdown_f` output from this directory is also used by the separate retrospective `lwdown` workflow.

The workflow is implemented within NASA's Land Information System (LIS) using the `eis-freshwater2` branch.

The methodology follows that described in Whitney et al. (2025). The broader NLDAS-3 forcing development is described in Maina et al. (in review), which should be cited when using this code and/or the resulting NLDAS-3 forcing datasets.

The workflow requires dynamic lapse-rate fields computed from the gridded MERRA-2 dataset prior to execution of the retrospective downscaling procedure, as described within the `eis-freshwater2` directory:

```text
lis/utils/nldas-3_forcing/dynamic_lapse_rates
```

## Generated Forcing Fields

This workflow generates hourly 1-km retrospective meteorological forcing fields derived from MERRA-2.
The resulting 1-km fields of:

- 2-m air temperature (`Tair_f`)
- specific humidity (`Qair_f`)
- surface pressure (`Psurf_f`)
- downward longwave radiation (`LWdown_f`)

are generated by this workflow as hourly intermediate forcing fields.

The workflow also outputs the dynamic lapse-rate field (`Lapserate`) applied during downscaling for diagnostic and quality-control purposes.

All forcing fields except `Lapserate` (i.e., `Tair_f`, `Qair_f`, `Psurf_f`, and `LWdown_f`) are merged into one daily NetCDF file per day by the merge utility in this directory.

The hourly `LWdown_f` output is retained for the downstream `retrospective/lwdown` workflow, where it is adjusted using CERES-derived downward longwave radiation before the final retrospective merge.

In the final retrospective merge workflow, the CERES-adjusted downward longwave field replaces the original hourly `LWdown_f` field generated here.

## Related Workflows

### Upstream Dependencies
This workflow depends on dynamic lapse-rate fields generated from MERRA-2 air temperature, elevation, and land-mask inputs.

Documentation and code for dynamic lapse-rate generation can be found within:

```text
lis/utils/nldas-3_forcing/dynamic_lapse_rates
```

The dynamic lapse-rate fields are generated prior to execution of the retrospective forcing workflow documented here. These lapse-rate fields are used by LIS during topographic downscaling of MERRA-2 meteorological forcing fields.

### Downstream Applications

The hourly outputs generated by this workflow are consumed by two downstream retrospective NLDAS-3 workflows.

#### CERES Downward Longwave Radiation Adjustment

The hourly `LWdown_f` field generated by this workflow is used by the retrospective `lwdown` workflow to adjust CERES-derived downward longwave radiation fields that have been bilinearly interpolated to the NLDAS-3 1-km grid.

Documentation and code for this workflow can be found within:

```text
lis/utils/nldas-3_forcing/retrospective/lwdown
```

#### Daily Forcing Merge

The hourly LIS outputs generated by this workflow are merged into one daily NetCDF file per day, with all 24 hourly timesteps preserved, by the merge utility in this directory.

The merged daily files are then used by the retrospective `merge` workflow, which assembles the final daily NLDAS-3 retrospective forcing files. In that final merge step, the original hourly `LWdown_f` generated here is replaced by the CERES-adjusted downward longwave field produced by the `retrospective/lwdown` workflow.

Documentation and code for the downstream retrospective merge workflow will be located within:

```text
lis/utils/nldas-3_forcing/retrospective/merge
```

## Workflow Summary

The retrospective forcing workflow:

1. Reads hourly MERRA-2 forcing inputs.
2. Applies terrain-based downscaling using dynamic lapse-rate fields.
3. Generates 1-km air temperature, humidity, pressure, and longwave radiation fields and records the dynamic lapse-rate field used during downscaling.
4. Writes hourly forcing fields that are merged into one daily file per day by the local merge utility.
5. Produces hourly `LWdown_f` fields for use by the `retrospective/lwdown` workflow and merged daily surface meteorology files for use by the `retrospective/merge` workflow.

## Configuration file settings

The `lis.config` file configures LIS to run in retrospective mode over the NLDAS-3 1-km domain using MERRA-2 meteorological forcing inputs. The LIS User Guide provides the full reference for LIS configuration options, including driver options, runtime options, parameter inputs, forcings, and model output configuration.

### Driver and Forcing Configuration

```text
Running mode:                           retrospective
Map projection of the LIS domain:       latlon
Number of nests:                        1
Number of surface model types:          1
Surface model types:                    LSM
Land surface model:                     none
Number of met forcing sources:          1
Met forcing sources:                    "MERRA2"
Blending method for forcings:           overlay
Topographic correction method (met forcing):  "lapse-rate and slope-aspect"
Spatial interpolation method (met forcing):   bilinear
Temporal interpolation method (met forcing):  "linear"
```

These settings configure LIS to run in retrospective mode on a latitude/longitude grid using MERRA-2 as the sole meteorological forcing source. The workflow does not run a land surface model. Instead, LIS is used as a meteorological forcing-generation and downscaling framework to generate forcing fields on the NLDAS-3 1-km grid.

The topographic correction method applies lapse-rate-based and slope/aspect-based adjustments during spatial downscaling. MERRA-2 fields are spatially interpolated using bilinear interpolation and temporally interpolated using linear interpolation.

### Runtime and Output Configuration

```text
Forcing variables list file:            ./forcing_variables.txt
Output methodology:                     "2d gridspace"
Output model restart files:             0
Output data format:                     netcdf
Output naming style:                    "3 level hierarchy"
Start mode:                             coldstart
Surface model output interval:          1hr
Undefined value:                        -9999
Model output attributes file:           './NOAHMP_OUTPUT_LIST.TBL'
```

These settings specify the forcing variables to be produced, the output format, and the output frequency. The workflow writes hourly NetCDF output on the 2-D model grid and does not write model restart files. Output variable metadata are controlled through `NOAHMP_OUTPUT_LIST.TBL`.

Each output file contains a single hourly forcing field. A separate Fortran merge utility distributed within this directory combines the hourly output files into one daily NetCDF file per day while preserving all 24 hourly timesteps. The hourly output files include all forcing variables generated by this workflow, including `LWdown_f` and `Lapserate`.

The example configuration uses placeholder dates for a sample run. For full retrospective production, the intended run period spans from 2000-12-31 00:00:00 through 2024-12-31 00:00:00, as noted in the comments within `lis.config`.

### Domain and Parameter Inputs

```text
LIS domain and parameter data file:     ./lis_input.nldas3.noahmp401.1km.land_and_inland_water.m2interp.nc
Landmask data source:                   LDT
Landcover data source:                  LDT
Elevation data source:                  LDT
Slope data source:                      LDT
Aspect data source:                     LDT
Greenness data source:                  LDT
```

The workflow uses an LDT-generated NLDAS-3 domain and parameter file, `lis_input.nldas3.noahmp401.1km.land_and_inland_water.m2interp.nc`, to define the target 1-km domain and static land-surface fields. The elevation, slope, and aspect fields are used by the topographic downscaling procedure. 

This parameter file is available from the NLDAS-3 S3 bucket. For additional information on accessing NLDAS-3 data products, see:
https://github.com/NASAWaterInsight/NLDAS-3

### MERRA-2 Forcing Settings

```text
MERRA2 forcing directory:       ./input/MET_FORCING/MERRA2/
MERRA2 use lowest model level forcing:     0
MERRA2 use 2m wind fields:                 0
MERRA2 use corrected total precipitation:  0
MERRA2 apply dynamic lapse rates:          1
MERRA2 dynamic lapse rate data directory:  ./lapse_rates_merra2/
MERRA2 apply double-sided dynamic lapse rate cutoff:  1
MERRA2 dynamic lapse rate filename prefix: MERRA2.lapse_rate.hourly.
MERRA2 dynamic lapse rate filename suffix: .nldas3.nc
```

These settings point LIS to the MERRA-2 forcing directory and enable use of precomputed dynamic lapse-rate fields during downscaling, following Whitney et al. (2025; see citation above). The lapse-rate files are expected to be located in `./lapse_rates_merra2/` and to follow the filename pattern:

```text
MERRA2.lapse_rate.hourly.<date>.nldas3.nc
```

The dynamic lapse-rate fields are generated separately using the workflow documented within the `eis-freshwater2` directory:

```text
lis/utils/nldas-3_forcing/dynamic_lapse_rates
```

The double-sided dynamic lapse-rate cutoff is applied within the LIS downscaling workflow to limit the magnitude of dynamic lapse-rate adjustments during forcing generation (±10 K km⁻¹ following Whitney et al., 2025; see citation above). Dynamic lapse rates exceeding these thresholds are replaced with the corresponding cutoff value prior to downscaling. The resulting cutoff-adjusted lapse-rate field is also written to the `Lapserate` output variable when enabled in `NOAHMP_OUTPUT_LIST.TBL` (see below).

### Tiling and Model Configuration

```text
Maximum number of surface type tiles per grid:    1
Maximum number of soil texture tiles per grid:    1
Maximum number of elevation bands per grid:       1
Maximum number of slope bands per grid:           1
Maximum number of aspect bands per grid:          1
Land surface model:                               none
Routing model:                                    "none"
Irrigation scheme:                                "none"
```

The configuration disables subgrid tiling beyond a single tile per grid cell and does not run a land surface model, routing model, irrigation scheme, or data assimilation instance. This keeps the workflow focused on meteorological forcing generation rather than land-surface simulation.

### Parallel Layout

```text
Number of processors along x:        20
Number of processors along y:        14
Halo size along x:                   0
Halo size along y:                   0
```

The sample configuration decomposes the domain across 280 MPI tasks using a 20 × 14 processor layout. The processor decomposition should be adjusted as needed to match the computational environment and execution configuration.

## Forcing Variable Selection

The file `forcing_variables.txt` specifies the meteorological forcing variables read from the MERRA-2 forcing dataset and made available to the LIS forcing framework.

Each entry contains:

```text
variable_name  selected?  vertical_levels  units
```

where:

- `selected?` indicates whether the variable is enabled.
- `vertical_levels` specifies the number of vertical levels associated with the variable.
- `units` specifies the physical units of the variable.

For the retrospective NLDAS-3 forcing workflow, all variables listed in the distributed example file are enabled (`selected? = 1`). The following MERRA-2 variables are used:

| Variable | Description |
|-----------|-------------|
| `Tair` | Near-surface air temperature |
| `Qair` | Near-surface specific humidity |
| `LWdown` | Incident longwave radiation |
| `Wind_E` | Eastward wind component |
| `Wind_N` | Northward wind component |
| `Psurf` | Surface pressure |
| `Rainf` | Total precipitation rate |
| `CRainf` | Convective precipitation rate |

## Output Variable Configuration

The file `NOAHMP_OUTPUT_LIST.TBL` controls which variables are written to the LIS output files and defines their metadata.

For the retrospective NLDAS-3 forcing workflow, the following output variables are generated:

| Variable | Units | Description |
|-----------|--------|-------------|
| `Tair_f` | K | Downscaled near-surface air temperature |
| `Qair_f` | kg kg⁻¹ | Downscaled near-surface specific humidity |
| `Psurf_f` | Pa | Downscaled surface pressure |
| `LWdown_f` | W m⁻² | Downscaled downward longwave radiation |
| `Lapserate` | K km⁻¹ | Dynamic lapse rate used during downscaling |

The `_f` suffix denotes forcing variables generated by the retrospective surface-forcing workflow. The `Lapserate` variable is included for diagnostic and quality-control purposes and records the dynamic lapse-rate field applied during downscaling. This output provides a direct record of the lapse-rate field used by LIS during generation of the retrospective NLDAS-3 forcing fields.

The variables listed above are written to the hourly LIS output files. The hourly `LWdown_f` variable generated by this workflow serves as the input to the downstream `retrospective/lwdown` workflow, which produces the CERES-adjusted downward longwave radiation field. During final retrospective forcing assembly, that CERES-adjusted field replaces the original `LWdown_f` generated here.

The merged daily files created by the local merge utility preserve the hourly timesteps and provide the input structure required by the downstream `retrospective/merge` workflow.

## Hourly-to-Daily Merge Utility

This directory includes a Fortran utility:

```text
merge_files_for_date_range.f90
```

This program merges the hourly LIS surface meteorology output files into one daily NetCDF file per day while preserving all 24 hourly timesteps.

The merge utility is distributed as Fortran source code and should be compiled locally by the user in their computing environment prior to execution.

### Compilation

The merge utility depends on the NetCDF Fortran library. Users should compile the Fortran source file locally using their site-specific compiler and NetCDF include/library paths.

### Usage

After compilation, the merge executable is run on the hourly LIS output directory to generate one merged daily file for each day in the requested date range.

The resulting merged daily files serve as the surface meteorology inputs to the downstream `retrospective/merge` workflow.
