# Dynamic Lapse Rate Generation for NLDAS-3

## Overview

This repository contains code used to generate dynamic near-surface air-temperature lapse-rate fields for the NASA North American Land Data Assimilation System Phase 3 (NLDAS-3) forcing system.

Dynamic lapse rates are computed from gridded 2-m air temperature, terrain elevation, and land-mask data. The resulting lapse-rate fields are used to downscale meteorological forcings to the 1-km NLDAS-3 modeling grid within the NASA Land Information System (LIS) framework.

The lapse-rate methodology follows the framework introduced by Rouf et al. (2020) and the implementation and configuration described in Whitney et al. (2025). The broader NLDAS-3 forcing development is described in Maina et al. (in review), which should be cited when using this code and/or the resulting NLDAS-3 forcing datasets.

## What Are Dynamic Lapse Rates?

In this context, *dynamic* lapse rates refer to lapse rates that are computed directly from the spatial relationship between air temperature and elevation at each time step and grid cell, rather than prescribing a single constant lapse rate over the domain.

At each land grid cell, lapse rates are estimated using a local linear regression between temperature differences (ΔT) and elevation differences (ΔZ) within a 3 × 3 neighborhood centered on the target cell.

This approach allows lapse rates to vary spatially and temporally in response to evolving atmospheric conditions and terrain characteristics.

---

## Methodology

For each land grid cell and time step:

1. A 3 × 3 neighborhood is constructed around the target grid cell.
2. Temperature differences (ΔT) and elevation differences (ΔZ) are computed relative to the center cell.
3. A linear regression is performed to estimate the local lapse rate, ΔT/ΔZ.
4. Quality-control filters are applied.
5. Water and shoreline cells receive a prescribed fallback lapse rate where appropriate.

The implementation follows Rouf et al. (2020) with modifications described in Whitney et al. (2025) to improve robustness and physical realism.

### Modifications from Rouf et al. (2020)

Following Whitney et al. (2025):

- Grid cells with fewer than five valid surrounding land neighbors, corresponding to locations with greater than approximately 50% water coverage in the 3 × 3 neighborhood, receive a static lapse rate of −6.5 °C km⁻¹.
- Shoreline-buffer and inland-water cells are assigned the fallback lapse rate to reduce artifacts near coastlines and water bodies.

During NLDAS-3 forcing generation, additional lapse-rate quality controls, including lapse-rate magnitude constraints described in Whitney et al. (2025), are applied within the LIS downscaling workflow rather than during dynamic lapse-rate generation itself. These modifications reduce unstable or nonphysical lapse-rate estimates in regions with limited terrain variability, sparse valid neighbors, coastlines, and inland water bodies.

## NLDAS-3 Applications

The generated dynamic lapse-rate fields are used during production of the NLDAS-3 1-km meteorological forcings. The dynamic lapse-rate fields generated by this repository are an intermediate product used within the NLDAS-3 forcing-generation system and are not themselves the final downscaled forcings.

### Retrospective Forcings

For the retrospective NLDAS-3 forcing record, dynamic lapse rates are generated from:

- MERRA-2 2-m air temperature, `T2M`
- MERRA-2 terrain elevation
- MERRA-2 land-mask information

These lapse rates are used within the LIS meteorological downscaling framework to produce the 1-km retrospective NLDAS-3 meteorological forcing dataset.

During retrospective forcing generation, a dynamic lapse-rate cap of ±10 °C km⁻¹ is applied within the LIS meteorological downscaling framework rather than during execution of `compute_dynamic_lapse_rates.py`. This processing is implemented within:

```text
lis/utils/nldas-3_forcing/retrospective/surface
```

See the documentation in that directory for additional details on the retrospective forcing-generation procedures, including the lapse-rate quality controls described in Whitney et al. (2025).

### Near-Real-Time Forcings

For near-real-time (NRT) NLDAS-3 production, dynamic lapse rates are generated from GEOS-ITbias air-temperature fields.

GEOS-ITbias inputs are bias-corrected GEOS-IT fields generated using MERRA-2 monthly climatologies spanning 2001–2024. These GEOS-ITbias temperature fields are used as input to the dynamic lapse-rate calculation, and the resulting dynamic lapse-rate fields are used within the LIS meteorological downscaling framework to generate 1-km meteorological forcings.

As in the retrospective workflow, a dynamic lapse-rate cap of ±10 °C km⁻¹ is applied during the LIS meteorological downscaling framework rather than during execution of `compute_dynamic_lapse_rates.py`. Documentation for the NLDAS-3 near-real-time forcing workflow is under development.

A companion repository documenting the GEOS-ITbias generation procedure and the NLDAS-3 near-real-time forcing-generation workflow is currently under development.

Forthcoming repositories will document:

- the use of GEOS-ITbias dynamic lapse rates for NLDAS-3 NRT forcing generation, and
- the generation of the GEOS-ITbias forcing inputs themselves.

## Elevation and Land-Mask Preprocessing

The dynamic lapse-rate script expects an elevation and land-mask NetCDF file containing:

- `ELEVATION`: terrain elevation in meters
- `LANDMASK`: binary land mask, where `1` indicates land and `0` indicates non-land

For the NLDAS-3 dynamic lapse-rate workflows, these files are:

```text
merra2.elevation_and_landmask.nc
geosit.elevation_and_landmask.nc
```

These files are derived from the corresponding MERRA-2 and GEOS-IT constant parameter files.

### Elevation

Elevation is derived from the `PHIS` field, which represents surface geopotential. The field is converted to elevation in meters using:

```text
ELEVATION = PHIS / 9.80665
```

where `9.80665 m s⁻²` is standard gravitational acceleration.

The time dimension is removed after verifying that the elevation field is constant through time.

### Land Mask

The binary land mask is derived from the fractional land and land-ice fields:

```text
LANDMASK_FRAC = FRLAND + FRLANDICE
```

A binary land mask is then created using a threshold of 0.5:

```text
LANDMASK = 1.0 where LANDMASK_FRAC >= 0.5
LANDMASK = 0.0 where LANDMASK_FRAC < 0.5
```

The time dimension is removed after verifying that the fractional land mask is constant through time.

### Output Structure

The preprocessed files contain `ELEVATION` and `LANDMASK` on the source meteorological grid with sorted latitude and longitude coordinates. Missing values are filled using `-9999.0`.

Example output variables:

```text
ELEVATION
LANDMASK
lat
lon
```

These files are then passed to `compute_dynamic_lapse_rates.py` using:

```text
--infile_Z
--infile_landmask
```

### `compute_dynamic_lapse_rates.py`

Generates dynamic lapse-rate fields from gridded temperature, elevation, and land-mask inputs.

The script supports:

- MERRA-2 retrospective production workflows
- GEOS-ITbias near-real-time production workflows
- Daily and hourly processing modes
- Optional clipping to a reference domain
- Optional resampling of elevation and land-mask datasets to the temperature grid
- Water-body handling and shoreline buffering
- User-configurable lapse-rate thresholds and fallback behavior
- Skip-existing, overwrite, and dry-run modes

Example commands for retrospective and NRT processing are included in the script documentation.

## Example Workflows

### MERRA-2 Retrospective Dynamic Lapse Rates

For retrospective MERRA-2 production, one lapse-rate output file is generated per day. Each output file preserves all hourly timesteps from the corresponding MERRA-2 input file. In the NLDAS-3 retrospective workflow, the output filename prefix includes `hourly` to indicate that the files contain hourly lapse-rate fields, even though the output granularity is daily.

The example below includes options for clipping the MERRA-2 domain to the
NLDAS-3 modeling domain using ``--clip_to_reference_bbox``. The clipping
extent is defined using the LIS input file
``lis_input.nldas3.noahmp401.1km.land_and_inland_water.m2interp.nc``,
which is available from the NLDAS-3 S3 bucket.

For additional information on accessing NLDAS-3 data products, see:
https://github.com/NASAWaterInsight/NLDAS-3

```bash
python compute_dynamic_lapse_rates.py \
  --infile_Z ./merra2.elevation_and_landmask.nc \
  --infile_landmask ./merra2.elevation_and_landmask.nc \
  --inpath_T ./data/MERRA2/temperature/ \
  --outpath ./outputs/lapse_rates_merra2/ \
  --yyyymmdd_start 20001231 \
  --yyyymmdd_end 20241231 \
  --infile_date_format YYYYMMDD \
  --outfile_date_format YYYYMMDD \
  --output_mode daily \
  --fname_in_pfx_T MERRA2.tavg1_2d_slv_Nx. \
  --fname_in_sfx_T .nc4 \
  --fname_out_pfx MERRA2.lapse_rate.hourly. \
  --fname_out_sfx .nldas3.nc \
  --landmask_trueval 1 \
  --min_land_neighbors 5 \
  --LR_forced_val -0.0065 \
  --save_units_as_per_km 1 \
  --clip_to_reference_bbox \
  --reference_grid_file ./lis_input.nldas3.noahmp401.1km.land_and_inland_water.m2interp.nc
```

### GEOS-ITbias Near-Real-Time Dynamic Lapse Rates

The NRT workflow computes dynamic lapse rates from GEOS-ITbias 2-m air-temperature inputs.

GEOS-ITbias inputs are generated by bias-correcting GEOS-IT using
MERRA-2 monthly climatologies derived from the 2001–2024 period.

The example below demonstrates processing of 24 hourly GEOS-ITbias files
covering a single simulation day. Because the GEOS-ITbias inputs have
already been clipped to the NLDAS-3 modeling domain, the command does not
include the ``--clip_to_reference_bbox`` or ``--reference_grid_file``
options.

```bash
python compute_dynamic_lapse_rates.py \
  --infile_Z ./geosit.elevation_and_landmask.nc \
  --infile_landmask ./geosit.elevation_and_landmask.nc \
  --inpath_T ./data/GEOSIT/temperature/ \
  --outpath ./outputs/lapse_rates_geosit/ \
  --yyyymmdd_start 20230430 \
  --yyyymmdd_end 20230501 \
  --start_datetime "2023-04-30 12:00" \
  --end_datetime "2023-05-01 12:00" \
  --Z_varin ELEVATION \
  --T_varin T2M \
  --landmask_varin LANDMASK \
  --time_varin time \
  --infile_date_format YYYY-MM-DDTHH \
  --outfile_date_format YYYY-MM-DDTHH \
  --output_mode hourly \
  --fname_in_pfx_T T2M_ \
  --fname_in_sfx_T .nc \
  --fname_out_pfx GEOS-ITbias.lapse_rate.hourly. \
  --fname_out_sfx .nldas3.nc \
  --landmask_trueval 1 \
  --min_land_neighbors 5 \
  --LR_forced_val -0.0065 \
  --save_units_as_per_km 1
```

### Whitney et al. (2025) Cascade–Sierra Dataset

The dynamic lapse-rate dataset accompanying Whitney et al. (2025) was generated using the same MERRA-2 temperature, elevation, and land-mask products described above. As in the NLDAS-3 retrospective workflow, one output NetCDF file was produced per day, with each file retaining all hourly time steps from the corresponding MERRA-2 input file. The output filename prefix includes `hourly` to indicate that each daily file contains hourly lapse-rate fields.

Unlike the NLDAS-3 retrospective workflow, the Whitney et al. (2025) dataset was generated only for the Sierra Nevada–Cascade study domain (approximately 34.495–49.505°N, 124.69–117.50°W). The modified R2020 configuration described in Whitney et al. (2025) was used, including:

- a minimum of five valid surrounding land neighbors before estimating a dynamic lapse rate,
- a fallback static lapse rate of −6.5 °C km⁻¹ when this criterion is not met, and
- a dynamic lapse-rate cap of ±10 °C km⁻¹ (applied directly during dynamic lapse-rate generation, rather than later within the LIS forcing workflow as in NLDAS-3).

The corresponding dataset is available from Zenodo:

Whitney, K. M., Kumar, S. V., Mocko, D., Pflug, J., Bolten, J. D., Maina, F. Z., Wrzesien, M. L., and Hain, C. R., 2026:
*Dynamic near-surface air-temperature lapse rates for the Cascade–Sierra study domain derived from MERRA-2 (2000–2020)* (Version 1.0.0) [Dataset].
Zenodo.
https://doi.org/10.5281/zenodo.21044739

To reproduce the study-domain dataset, the workflow uses the `--clip_to_reference_bbox` option. The reference grid defining the study-domain bounding box was generated using the Land Data Toolkit (LDT) distributed with NASA's Land Information System (LIS). Users wishing to reproduce this workflow may generate an equivalent reference grid for the study domain using LDT. Documentation is available in the LDT User Guide:

https://nasa-lis.github.io/LISF/LDT_users_guide/LDT_users_guide.html

Example command:

```bash
python compute_dynamic_lapse_rates.py \
  --infile_Z ./merra2.elevation_and_landmask.nc \
  --infile_landmask ./merra2.elevation_and_landmask.nc \
  --inpath_T ./data/MERRA2/temperature/ \
  --outpath ./outputs/lapse_rates_merra2/ \
  --yyyymmdd_start 20000601 \
  --yyyymmdd_end 20201231 \
  --infile_date_format YYYYMMDD \
  --outfile_date_format YYYYMMDD \
  --output_mode daily \
  --fname_in_pfx_T MERRA2.tavg1_2d_slv_Nx. \
  --fname_in_sfx_T .nc4 \
  --fname_out_pfx MERRA2.lapse_rate.hourly. \
  --fname_out_sfx .nc \
  --landmask_trueval 1 \
  --min_land_neighbors 5 \
  --LR_forced_val -0.0065 \
  --save_units_as_per_km 1 \
  --min_lapse_rate_cutoff -0.01 \
  --max_lapse_rate_cutoff 0.01 \
  --clip_to_reference_bbox \
  --reference_grid_file /path/to/lis_input.cascade_sierra.nc
```

## Notes

- Existing outputs are skipped unless `--force` is provided.
- Use `--dryrun` to preview planned outputs without writing files.
- Daily outputs preserve all time steps; no temporal averaging is applied.
- Bounding-box clipping and target-grid resampling are separate steps: clipping limits the domain, while resampling aligns elevation and land-mask fields to the temperature grid when needed.
- For MERRA-2 and GEOS-ITbias datasets already on a common grid, no special preprocessing is usually required beyond correct variable names and filename settings.
